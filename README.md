# Сайты для познания: дашборд

Каждый час сборщик обходит 112 ресурсов подборки и складывает новые посты в репозиторий. На их основе собирается сайт-дашборд на GitHub Pages.

- **Пульс подборки.** Тепловая карта «разделы × 14 дней» с итогами по дням. Клик по разделу или клетке выбирает раздел.
- **Бегущая строка, «Случайная находка» и «Случайный справочник».** Случайная статья или справочник из выбранных разделов. Переключатель темы: авто / светлая / тёмная.
- **Лента.** Свежие посты по дням. Можно выбрать один или несколько разделов (Философия, История…), период (24 ч / 3 / 7 / 30 дней) и язык, а также искать по словам. Выбор разделов попадает в адрес страницы, например `…/#s=filosofiya,istoriya`, поэтому его можно сохранить в закладки.
- **Справочники.** 23 сайта без потока статей: карточки с кратким описанием, по разделам.
- **Все источники.** Все 112 сайтов с описаниями, поиском и статусом: работает / давно без постов / не пускает сборщик / ошибка / справочник. Там же видно, каким способом собирается сайт, и любой источник можно скрыть из ленты.
- **Числа у разделов** — индексы УДК (Универсальной десятичной классификации): 1 — философия, 17 — этика, 572 — антропология, 94 — история, 16 — логика, 008 — культура, 7 — искусство, 81 — лингвистика, 004 — информатика, 51 — математика, 001 — наука в целом, 159.9 — психология, 33 — экономика, 5 — естественные науки.
- Посты, вышедшие после вашего прошлого визита, отмечены как «новое».

## Как собираются посты

| Режим в `sources.yaml` | Что делает сборщик |
|---|---|
| `feeds:` | Читает указанные RSS/Atom-ленты. 55 лент проверены 17.10.2026 |
| `mode: auto` | Ищет сам: подсказку `feed_hint` → `<link rel="alternate">` на странице → типовые адреса (`/feed`, `/rss`…) → карту сайта `sitemap.xml` → разбор страницы со списком статей. Найденный способ запоминается на 7 дней |
| `telegram:` | Дополнительно берёт посты из публичного Telegram-канала (`t.me/s/…`) |
| `mode: reference` | Справочники и инструменты (WALS, НКРЯ, PhilPapers…): только ссылка, постов у них нет |
| `list_url`, `match`, `html`, `unique` | Ручная настройка для трудных сайтов: своя страница со списком, шаблон адресов статей, CSS-селекторы, различение записей по заголовку |

Как ведёт себя сборщик:

- Представляется своим User-Agent.
- Ленты запрашивает с условными заголовками, так что неизменившаяся лента отвечает коротким «304».
- Для разбора страниц и карт сайтов соблюдает `robots.txt`.
- На первом прогоне статьи без даты публикации, найденные на странице сайта, не попадают в «новое». Иначе в ленту хлынул бы весь архив главной страницы.

## Запуск: один раз, около 10 минут

1. **Создайте репозиторий на GitHub**, например `poznanie`. Сделайте его **публичным**: тогда расписание Actions и GitHub Pages бесплатны. В репозитории хранятся только заголовки, ссылки и короткие анонсы.
2. **Загрузите файлы проекта.** Проще всего через [GitHub Desktop](https://desktop.github.com/): File → Add Local Repository → папка проекта → Publish. Или в терминале, из папки проекта:
   ```bash
   git init && git add . && git commit -m "Дашборд: первая версия"
   git branch -M main
   git remote add origin https://github.com/<ваш-логин>/poznanie.git
   git push -u origin main
   ```
3. **Settings → Actions → General → Workflow permissions:** выберите *Read and write permissions* и сохраните.
4. **Settings → Pages → Build and deployment → Source:** выберите *GitHub Actions*.
5. **Actions → «Сбор постов» → Run workflow.** Первый прогон дольше обычных, примерно 5–15 минут: сборщик ищет способ для 34 сайтов в режиме auto. Дальше прогоны займут 1–3 минуты.
6. Откройте `https://<ваш-логин>.github.io/poznanie/`. После этого дашборд обновляется сам, в :17 каждого часа.

## Если источник с ошибкой

Откройте вкладку «Источники» и посмотрите сообщение у источника. Что обычно помогает:

- **Есть лента, но сборщик её не нашёл:** впишите её в `feeds:`.
- **Сайт без RSS, но с Telegram-каналом:** добавьте `telegram: имя_канала`.
- **Эвристика тянет со страницы мусор:** задайте селекторы:
  ```yaml
  html: {item: "article", link: "a", title: "h2"}
  ```
- **«Не пускает сборщик»:** сайт просит роботов не заходить (robots.txt) или отвечает серверам GitHub кодом 403. Остаётся лента на другом адресе или Telegram.
- **«сайт не отвечает» / HTTP 403:** часть российских сайтов не отвечает зарубежным серверам, а машины GitHub находятся в США. Такие источники позже можно собирать отдельным сборщиком с вашего Mac.

После правки `sources.yaml` закоммитьте изменения. Следующий прогон подхватит их сам.

## Локально, в JupyterLab или терминале

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python -m collector --only aeon,elementy -v     # прогон по выбранным источникам
python -m dashboard                             # собрать public/
python -m http.server -d public 8000            # открыть http://localhost:8000
python -m pytest -q                             # тесты (20 штук, без сети)
```

Посмотреть дизайн до первого запуска можно на демо-данных. Заголовки в них — заглушки:

```bash
python tools/demo_data.py /tmp/demo-data
python -m dashboard --data /tmp/demo-data --out /tmp/demo
python -m http.server -d /tmp/demo 8000
```

## Где лежат данные

- `data/posts/ГГГГ-ММ.jsonl` — все собранные посты по месяцам, по одному JSON на строку. Поля: `id, source, url, title, summary, published, seen, via`. Это полный архив с первого дня, на нём будет строиться поиск.
- `data/state.json` — состояние источников: найденный способ, ETag, последний пост, история прогонов.
- `public/` — собранный сайт. Не коммитится, публикуется прямо из workflow.

Дашборд показывает последние 31 день. Архив в `data/posts/` не обрезается.

## Ограничения GitHub

- Расписание соблюдается «примерно»: при нагрузке запуск сдвигается на 5–20 минут.
- В публичном репозитории GitHub отключает расписание после 60 дней без активности. Сборщик коммитит данные почти каждый час, этого обычно достаточно. Если придёт письмо об отключении, нажмите *Enable workflow* во вкладке Actions.

## Дальше: поиск по архиву

Данные уже хранятся так, чтобы поиск добавлялся без переделок:

1. Полнотекстовый поиск: скрипт строит SQLite с FTS5 из `data/posts/*.jsonl`. На статическом сайте он работает через sql.js или Pagefind, без сервера.
2. Выкачать архив прошлых лет по картам сайтов (`sitemap.xml`).
3. Смысловой поиск и вопросы к архиву: эмбеддинги заголовков и анонсов плюс RAG.

## Устройство

```
sources.yaml              112 источников, 14 разделов с индексами УДК
collector/                сборщик: run.py (прогон), fetch.py (HTTP, robots.txt),
  methods/                feed, discover, sitemap, page, telegram
  store.py                JSONL по месяцам + state.json
dashboard/                build.py (JSON для страницы) + static/ (HTML, CSS, JS)
.github/workflows/        collect.yml — раз в час; tests.yml — тесты при изменении кода
tests/                    офлайн-тесты на фикстурах
tools/                    генератор sources.yaml и демо-данные
```
