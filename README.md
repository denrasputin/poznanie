# Сайты для познания: дашборд

Раз в три часа сборщик обходит 111 ресурсов подборки и складывает новые посты в репозиторий. На их основе собирается сайт-дашборд на GitHub Pages; его можно установить на телефон как приложение.

Четыре вкладки: **Лента · Закладки · Поиск · Ещё**. Неприметная кнопка «i» рядом с названием открывает инструкцию с картинками; при первом заходе над лентой видна короткая подсказка из трёх шагов.

- **Лента** — главный экран. Сверху одна цифра: сколько новых постов с прошлого визита (или за сутки) и когда было обновление.
- **Фильтры** — одна кнопка над лентой открывает панель (на телефоне выезжает снизу): разделы, период, язык, «только заголовки». Рядом строка-сводка того, что выбрано, и «сбросить». Разделы попадают в адрес страницы (`…/#s=filosofiya,nauka`), его можно сохранить в закладки.
- **Главное** — сверху 1–3 материала за сутки с сайтов, которые пишут редко (новостные сайты, у которых в среднем 2 поста в день и больше, сюда не попадают).
- **Меньше шума** — сайт, выпустивший за день 4 поста и больше, свёрнут в одну строку «Код Дурова — 18 постов за день». Одна и та же новость с разных сайтов показана один раз: «и ещё в 2 источниках». Материалы без даты публикации собраны одной строкой в конце ленты.
- **«Ещё на эту тему»** — под многими статьями: похожие материалы из всего архива (сравнение слов заголовка и анонса при сборке сайта, без внешних сервисов).
- **«Новое»** — красная полоска у постов, вышедших после конца прошлого визита. Визит — пока сайт открыт и между заходами меньше получаса; перезагрузка страницы метки не сбрасывает.
- **Карточки** — кнопка в шапке: статьи по одной, как в приложениях знакомств. Свайп вправо — открыть статью (или положить в очередь, если так выбрано в настройках), влево — следующая, вверх — в закладки; на компьютере — стрелки, ↓ возвращает предыдущую карточку. «По порядку» идёт от новых и помнит, где вы остановились; «Вперемешку» — случайные находки (заменили прежний кубик).
- **Сайт подстраивается** — открытые статьи, закладки и пропуски в карточках запоминаются в браузере: статьи с интересных вам сайтов поднимаются выше внутри дня, чаще попадают в «Главное» и в карточки «вперемешку». Посмотреть и сбросить — в «Ещё».
- **Закладки** — значок у каждой статьи. Список хранится в браузере: его можно сохранить копией в файл и восстановить, а также синхронизировать между устройствами через секретный gist на GitHub (ключ с правом только `gist`, вводится на каждом устройстве один раз).
- **Поиск** — одно поле: источники, свежие статьи и весь архив с первого дня (Pagefind: понимает формы русских слов, работает без сервера). Фильтр по разделу, сортировка по смыслу или по дате, примеры запросов и последние запросы.
- **Ещё** — настройки (тема, порядок внутри дня, что делает свайп вправо), каталог из источников и 25 справочников с переключателем «в ленте», «Что вам интересно», синхронизация закладок, «Пульс за 14 дней» и «Состояние сборщика». Разовый сбой проблемой не считается: «Не работает» появляется после трёх неудачных запусков подряд.
- **Шрифты** (Golos Text и Literata) и значки сайтов лежат на самом сайте: страница не обращается к Google и открывается без сети.
- **Разделы** (9) подписаны индексами УДК (Универсальной десятичной классификации) — они видны в подсказке при наведении: 1 — философия, 16 — критическое мышление, 159.9 — психология, 001 — идеи и эссе, 9 — история и общество, 7 — культура и искусство, 8 — литература и язык, 5 — наука и математика, 004 — технологии.

## Как собираются посты

| Режим в `sources.yaml` | Что делает сборщик |
|---|---|
| `feeds:` | Читает указанные RSS/Atom-ленты. 55 лент проверены 17.10.2026 |
| `mode: auto` | Ищет сам: подсказку `feed_hint` → `<link rel="alternate">` на странице → типовые адреса (`/feed`, `/rss`…) → карту сайта `sitemap.xml` → разбор страницы со списком статей. Найденный способ запоминается на 7 дней |
| `telegram:` | Дополнительно берёт посты из публичного Telegram-канала (`t.me/s/…`) |
| `mode: reference` | Справочники и инструменты (WALS, НКРЯ, PhilPapers…): только ссылка, постов у них нет |
| `list_url`, `match`, `html`, `unique` | Ручная настройка для трудных сайтов: своя страница со списком, шаблон адресов статей, CSS-селекторы, различение записей по заголовку |

Как ведёт себя сборщик:

- Представляется своим User-Agent.
- Ленты запрашивает с условными заголовками, так что неизменившаяся лента отвечает коротким «304».
- Для разбора страниц и карт сайтов соблюдает `robots.txt`.
- На первом прогоне статьи без даты публикации, найденные на странице сайта, не попадают в «новое». Иначе в ленту хлынул бы весь архив главной страницы.
- Если у статьи без даты номер в адресе (`/materials/621`) не больше уже виденного, это старый материал, всплывший на главной, а не новый пост.
- Сбой сети или ответ сервера 5xx — ещё две попытки с паузой. Ответ 429 («заходите реже») и недоступный robots.txt считаются временными сбоями, а не запретом.
- Раз в два месяца сборщик обновляет значки сайтов (`data/favicons/`), чтобы страница не обращалась за ними к Google.
- Если за один прогон не ответило больше половины сайтов, это сбой сети на стороне GitHub: неудачи источникам не засчитываются.
- Испорченная строка в файле с постами или испорченный `state.json` не останавливают сбор и сайт: строка пропускается с предупреждением, а `state.json` откладывается в `state.json.broken`.
- Источники, удалённые из `sources.yaml`, сборщик сам убирает из `state.json`.

## Запуск: один раз, около 10 минут

1. **Создайте репозиторий на GitHub**, например `poznanie`. Сделайте его **публичным**: тогда Actions и GitHub Pages бесплатны. В репозитории хранятся только заголовки, ссылки и короткие анонсы.
2. **Загрузите файлы проекта.** Проще всего через [GitHub Desktop](https://desktop.github.com/): File → Add Local Repository → папка проекта → Publish. Или в терминале, из папки проекта:
   ```bash
   git init && git add . && git commit -m "Дашборд: первая версия"
   git branch -M main
   git remote add origin https://github.com/<ваш-логин>/poznanie.git
   git push -u origin main
   ```
3. **Settings → Actions → General → Workflow permissions:** выберите *Read and write permissions* и сохраните.
4. **Settings → Pages → Build and deployment → Source:** выберите *GitHub Actions*.
5. **Создайте ветку `data` для данных** (один раз, из папки проекта):
   ```bash
   git switch --orphan data && mkdir -p posts && touch posts/.gitkeep && git add posts && git commit -m "Данные" && git push -u origin data && git switch main
   ```
6. **Actions → «Сбор постов» → Run workflow.** Первый прогон дольше обычных, примерно 5–15 минут: сборщик ищет способ для 30 сайтов в режиме auto. Дальше прогоны займут 1–3 минуты.
7. Откройте `https://<ваш-логин>.github.io/poznanie/`. После этого дашборд обновляется сам.
8. **Чтобы сбор шёл точно раз в три часа**, настройте внешний «будильник» — [docs/external-trigger.md](docs/external-trigger.md). Встроенное расписание GitHub часто сдвигает и пропускает запуски.

Как устроена автоматизация:

- **«Сбор постов»** (`collect.yml`) — раз в три часа обходит сайты и сохраняет данные в ветку `data`. Чаще не бывает: если прошлый сбор был меньше 2,5 часа назад, запуск пропускается (вручную можно собрать вне очереди галочкой при запуске). Код и история изменений в `main` не засоряются тысячами коммитов «Данные: …».
- **«Публикация сайта»** (`deploy.yml`) — запускается после каждого сбора (даже неудачного — тогда из последних сохранённых данных) и при правке дизайна или `sources.yaml`. Перед выкладкой прогоняет тесты и проверяет собранный сайт; если что-то не так, остаётся прежняя версия.
- **«Тесты»** (`tests.yml`) — при изменении кода и `sources.yaml`: опечатка в списке источников ловится до того, как сломает сбор.

## Если источник с ошибкой

Откройте вкладку «Источники» → «Состояние сборщика» и посмотрите сообщение у источника. Что обычно помогает:

- **Есть лента, но сборщик её не нашёл:** впишите её в `feeds:`.
- **Сайт без RSS, но с Telegram-каналом:** добавьте `telegram: имя_канала`.
- **Эвристика тянет со страницы мусор:** задайте селекторы:
  ```yaml
  html: {item: "article", link: "a", title: "h2"}
  ```
- **«Не пускает сборщик»:** сайт просит роботов не заходить (robots.txt) или отвечает серверам GitHub кодом 403. Остаётся лента на другом адресе или Telegram.
- **«сайт не отвечает» / HTTP 403:** часть российских сайтов не отвечает зарубежным серверам, а машины GitHub находятся в США. Такие источники позже можно собирать отдельным сборщиком с вашего Mac.

После правки `sources.yaml` закоммитьте изменения. Следующий прогон подхватит их сам.

## Локально, в JupyterLab или терминале

Нужен Python 3.12 (как на GitHub). Данные лежат в ветке `data`; удобнее всего подключить её папкой `data/`:

```bash
python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt pytest
git fetch origin data && git worktree add data data   # ветка data -> папка data/
python -m collector --only aeon,elementy -v           # прогон по выбранным источникам
python -m dashboard                                   # собрать public/ (с поиском по архиву)
python -m dashboard --check                           # проверить собранный сайт
python -m http.server -d public 8000                  # открыть http://localhost:8000
python -m pytest -q                                   # тесты (без сети)
```

Посмотреть дизайн без настоящих данных можно на демо-данных. Заголовки в них — заглушки:

```bash
python tools/demo_data.py /tmp/demo-data
python -m dashboard --data /tmp/demo-data --out /tmp/demo
python -m http.server -d /tmp/demo 8000
```

Иконки приложения и картинка для превью ссылок рисуются скриптом `tools/make_images.py` (нужен Pillow); PNG лежат в `dashboard/static/`.

## Где лежат данные

Всё в ветке `data` (в `main` её нет):

- `posts/ГГГГ-ММ.jsonl` — все собранные посты по месяцам, по одному JSON на строку. Поля: `id, source, url, title, summary, published, seen, via`. Полный архив с первого дня; по нему строится поиск.
- `state.json` — состояние источников: найденный способ, ETag, последний пост, число неудач подряд, история прогонов.
- `favicons/` — значки сайтов.

`public/` — собранный сайт. Не коммитится, публикуется прямо из workflow. Лента показывает последние 31 день: две недели грузятся сразу (`posts.json`), остальное — при выборе «30 дней» (`posts-older.json`). Архив не обрезается. Похожие статьи лежат в `related.json` и загружаются, только когда их раскрывают.

## Ограничения GitHub

- Расписание соблюдается «примерно»: при нагрузке запуск сдвигается на 5–20 минут.
- В публичном репозитории GitHub отключает расписание после 60 дней без активности. Сборщик коммитит данные несколько раз в день, этого обычно достаточно. Если придёт письмо об отключении, нажмите *Enable workflow* во вкладке Actions.

## Дальше

1. Выкачать архив прошлых лет по картам сайтов (`sitemap.xml`) — поиску станет из чего выбирать.
2. Смысловой поиск и вопросы к архиву: эмбеддинги заголовков и анонсов плюс RAG.
3. Сборщик на Mac для российских сайтов, которые не отвечают серверам GitHub в США, и для «Артгида» и Symmetry.

## Устройство

```
sources.yaml              111 источников, 9 разделов с индексами УДК
collector/                сборщик: run.py (прогон), fetch.py (HTTP с повторами, robots.txt),
  methods/                feed, discover, sitemap, page, telegram
  store.py                JSONL по месяцам + state.json
dashboard/                build.py (JSON для страницы, проверка сайта), archive.py (поиск Pagefind),
                          similar.py (повторы новостей и похожие статьи), favicons.py (значки сайтов),
                          static/ (HTML, CSS, JS, service worker, шрифты, иконки)
.github/workflows/        collect.yml — сбор; deploy.yml — публикация; tests.yml — тесты
docs/                     external-trigger.md — внешний «будильник» для регулярного сбора
tests/                    офлайн-тесты на фикстурах
tools/                    генератор sources.yaml, демо-данные, рисование иконок
```
